# Шаблоны проектов для wk

CLI живёт в отдельном соседнем репозитории `../wk`; его сборка и devShell
описаны в `../wk/README.md`. Это согласованное с указанием заказчика размещение
реализации шаблонов проектов (см. `../SPEC.md`, раздел 4.3).

Администратор кладёт YAML в `schema/project-templates/<id>.yaml` репозитория
вики и перезапускает сервис. Загрузчик добавляет шаблоны к реестру:

- `GET /api/v1/schema` содержит `project_templates`, отображение ID → шаблон.
- `invalid_project_templates` в том же ответе содержит карантин: имя файла
  без расширения → фиксированная причина ошибки, без содержимого файла.
- `GET /api/v1/schema/project-templates/{id}` возвращает один шаблон.
- Применяется существующая авторизация Reader, включая ограничения анонимного
  доступа сервера. Новых ролей или обходов авторизации нет.

```yaml
id: go-service
title: Go HTTP-сервис
profile: go-service
scopes: [lang:go]
components:
  - {name: api, kind: svc, lang: LANG-go}
files:
  - {path: main.go, content: "package main\nfunc main() {}\n"}
policy_blocks:
  - {file: AGENTS.md, profile: go-service}
```

Указанные профили и scopes должны существовать. ID равен имени файла без
расширения. Все модели строгие: неизвестные поля, в том числе hooks/exec,
отвергаются. Файлы: максимум 200, каждый ≤ 256 КиБ UTF-8, сумма ≤ 2 МиБ.
Пути относительные, без `..`, `.git`, пустых сегментов, обратных слэшей,
Windows drive letters и контрольных разделителей. Запись манифеста клиент
выполняет сам. Повторные файлы, компоненты, блоки политик и конфликты
файл/каталог запрещены. Симлинки и фактическое положение путей при применении
дополнительно проверяет клиент.

Некорректный YAML, нарушение структуры, несовпадение ID с именем файла или
ссылки на отсутствующие профили/scopes отправляют шаблон в карантин. Остальные
шаблоны и сервис продолжают работать. Удаление профиля или scope может отправить
в карантин ранее корректный шаблон, даже если сам файл шаблона не менялся.

`GET /api/v1/schema/project-templates/{id}` возвращает `E_TEMPLATE_INVALID` (422)
для карантинного шаблона и `E_TEMPLATE_UNKNOWN` (404) для отсутствующего ID.
`wk init --template` при таком отказе завершается до записи проекта; автоматического
перехода к созданию без шаблона или к кешу нет. CLI показывает HTTP-статус и код
ошибки сервера, не выводя его сообщение и подробности.

При загрузке каждый карантинный шаблон даёт одну строку WARNING с ID и причиной.
`wikisvc lint` возвращает по одной ошибке `E_TEMPLATE_INVALID` с путём к файлу
и завершается с кодом 1. Проверяйте lint после административных изменений схемы,
до рестарта. После исправления и перезагрузки реестра шаблон выходит из карантина.
Ошибки основных частей схемы (профили, типы страниц, relations и scopes)
по-прежнему прерывают загрузку; изоляция относится только к шаблонам проектов.

Код загрузчика не исполняет содержимое шаблонов и не делает сетевых запросов.
Существующее ограничение proposals на файлы в `wiki/` не изменено.

Проверка: `nix develop -c pytest -q tests/test_project_templates.py`, затем
общие `just lint`, `pytest --cov --cov-report=term-missing` и `nix flake check`.
