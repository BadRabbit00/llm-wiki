# ADR-0002 — Поиск BM25 и граф связей без графовой БД и эмбеддингов
status: superseded | date: 2026-10-02 | replaced_by: ADR-0018

## Контекст

Агенту нужен релевантный контекст: поиск по тексту и соседи по связям страниц. Первая версия
(2026-09-30) держала выключенную заготовку эмбеддингов; к этапу M3 медленным оказался обход графа.

## Решение

Поиск — BM25 через SQLite FTS5 со стеммингом, граф — таблицы связей в том же индексе с обходом
SQL-запросами (`GraphStore`, единственный адаптер — SQLite). Заготовка эмбеддингов удалена.

## Почему

- на небольшом корпусе BM25 + граф уже дают хороший результат (`ref/wiki-service-spec-v1.md`, раздел 18);
- граф — производный индекс; замер показал, что тормозил запрос, а не хранилище: переписанный обход
  в 100–250 раз быстрее (`ref/policy-layer-spec.md`, «Принятые решения»);
- нет модели эмбеддингов — ядро остаётся без LLM (ADR-0003).

## Что рассматривали и отвергли

| вариант | почему нет |
|---|---|
| внешняя графовая БД | синхронизация с git, второй источник правды |
| векторный поиск (pgvector, эмбеддинги) | нужен провайдер модели в ядре; на этом объёме не нужен |

## Последствия

- выдача не раскрывает числовой BM25 `score` (он раскрывал статистику скрытых страниц), только порядок;
- при росте корпуса качество поиска может потребовать векторов — это новое решение;
- затрагивает: LIB-wikisvc-core, RES-index-db, SVC-wikisvc, SVC-wikisvc-mcp.
