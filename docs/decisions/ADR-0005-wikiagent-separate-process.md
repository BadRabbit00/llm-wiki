# ADR-0005 — wikiagent отдельным процессом с изоляцией допусков
status: accepted | date: 2026-10-02

## Контекст

Чат, разбор книг и самолечение требуют модели (ADR-0003). Агент действует от имени людей с разными
допусками и не должен получить права больше, чем у вызывающего, или принять своё предложение.

## Решение

SVC-wikiagent — отдельный процесс со своим API (порт 8788) и базой RES-agent-db. В wikisvc он ходит
по HTTP постоянным токеном `kind=agent` с ролью writer (CFG-wikiagent.WIKIAGENT_TOKEN) через `WikiClient`
с фиксированным списком маршрутов: операций принятия, повышения, снятия и отката в нём нет.

## Почему

- ядро остаётся без LLM;
- принять изменение может только человек (INV-human-decides, INV-agent-rule-inert);
- допуск вызывающего должен быть не ниже допуска токена агента, иначе корпус агента утечёт
  (INV-agent-clearance-ceiling); человеческие токены в `agent.db` не хранятся.

## Что рассматривали и отвергли

| вариант | почему нет |
|---|---|
| умный ввод внутри wikisvc | ломает ADR-0003 |
| агент с прямым доступом к файлам и БД | обходит проверки и права API |

## Последствия

- в ENV-prod агент видит `/var/lib/llm-wiki` только на чтение, кроме `agent/` (`deploy/run.sh`);
- анонимный вызов агента запрещён; агент ждёт wikisvc и модель до старта;
- затрагивает: SVC-wikiagent, SVC-wikisvc, RES-agent-db, RES-llama-server.
