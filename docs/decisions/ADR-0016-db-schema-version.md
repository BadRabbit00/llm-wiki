# ADR-0016 — Версия схемы баз в PRAGMA user_version
status: accepted | date: 2026-10-13

## Контекст

От старого образа на мигрированной базе защищал только откат из архива. Запущенный вручную старый образ
молча работал на незнакомой схеме, а его миграции могли менять чужие таблицы.

## Решение

`state.db`, `agent.db` и `wiki.db` записывают версию схемы в `PRAGMA user_version`
(`src/wikisvc/storage/db_version.py`). Код проверяет её до миграций и отказывается работать с базой новее
себя — ERR-schema_newer (500). База без версии (0) считается старой и мигрирует. Версия только растёт.
Индекс производный: `wikisvc reindex --full` выбрасывает индекс новее себя и собирает заново.

## Почему

- старый образ не стартует на чужой схеме, а не портит её;
- откат обновления: архив возвращает `state.db` и `agent.db` той версии, индекс пересобирает прежний образ;
- тест хранит отпечаток каждой схемы рядом с версией: изменение схемы без повышения версии роняет тест.

## Что рассматривали и отвергли

| вариант | почему нет |
|---|---|
| полагаться только на откат из архива | ручной запуск старого образа не защищён |

## Последствия

- при восстановлении теряется TBL-wikisvc-core.index.delivery_stats: индекс не входит в копии;
- затрагивает: RES-state-db, RES-index-db, RES-agent-db, LIB-wikisvc-core, SVC-wikiagent, SVC-updater.
