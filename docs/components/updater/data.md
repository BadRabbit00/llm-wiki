# updater: данные

> Баз данных, кэша и очередей у компонента нет. Он владеет двумя наборами файлов на хосте. Данные служб (`var/lib/llm-wiki/*`, `etc/llm-wiki`) ему не принадлежат: он только архивирует и восстанавливает их целиком, не разбирая содержимое.

## Файлы и объекты

### BKT-updater.state-dir — Состояние демона
status: implemented | owner: SVC-updater | store: RES-host

- path: `/var/lib/llm-wiki-updater/state.json` (флаг `state-dir`, CFG-updater.state-dir; каталог создаёт systemd как `StateDirectory`, режим 0700)
- content: FMT-updater.state — канал, предложенное обновление, итог последней проверки и последняя операция с журналом шагов (DTO-updater.State); один файл, десятки килобайт
- access: пишет и читает только демон (root); файл 0600; наружу отдаётся через API-updater.status
- lifecycle: создаётся при первом старте; перезаписывается атомарно при каждом изменении шага; хранится только последняя операция, история прошлых не ведётся. Находится вне восстанавливаемых данных: откат архива его не затрагивает
- pii: имя или идентичность администратора, подтвердившего обновление (`started_by`); секретов нет
- written by: API-updater.channel, API-updater.apply, JOB-updater.check, JOB-updater.apply

### BKT-updater.pre-update-archives — Архивы перед обновлением
status: implemented | owner: SVC-updater | store: RES-host

- path: `/var/backups/llm-wiki/pre-update-<id операции>-<тег>.tar.gz` (флаг `backup-dir`, CFG-updater.backup-dir)
- content: `tar -czf` от корня файловой системы с путями `var/lib/llm-wiki/wiki`, `var/lib/llm-wiki/state`, `var/lib/llm-wiki/agent`, `etc/llm-wiki` (репозиторий вики, состояние wikisvc, данные wikiagent и конфигурация, включая `image.env`); индекс поиска не входит, он перестраивается. Размер равен размеру данных
- access: каталог создаётся с правами 0700, если его нет; файл 0600; читает только root; из API недоступны (в состоянии виден лишь путь `archive`)
- lifecycle: создаётся после остановки служб (шаг `archive`); неполный архив удаляется при ошибке `tar`. После успешного обновления остаются три новейших `pre-update-*.tar.gz`, остальные удаляются шагом `prune`; ночной бэкап чистит только `data-*.tar.gz`, поэтому эти файлы без `prune` копились бы вечно. Архивы неудачных, откатанных и прерванных операций не чистятся до следующего успешного обновления (после него общий лимит три применяется ко всем)
- pii: содержимое вики и состояния — как у самих данных; секреты из `etc/llm-wiki` (токены и ключи служб) попадают в архив, права 0600 это единственная защита
- written by: JOB-updater.apply

## Что демон меняет рядом

| что | когда | зачем |
|---|---|---|
| `/etc/llm-wiki/image.env` (FMT-updater.image-env) | шаг `switch`, откат восстанавливает из архива | закрепить новый digest |
| `/etc/llm-wiki/image.env.previous` | перед `switch` | прежняя строка для ручного отката |
| `<путь данных>.failed-<id операции>` | при откате (`Restore`) | данные неудавшегося обновления переименованы, а не удалены, для разбора; ничем не чистятся |
