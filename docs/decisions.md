# Решения реализации

1. Код находится в `backend/`, контент — в соседнем `wiki/`. Dev shell задаёт
   `WIKI_ROOT=../wiki`; состояние и индекс лежат в `backend/.dev/`, вне контента.
2. Обязательный объём — этапы 0–7. Провайдер эмбеддингов и NixOS-модуль
   отложены до этапа 8. Аудит через API и лимит запросов на токен реализованы.
3. Все Python-зависимости, включая `mcp` и `pystemmer`, проверены через `nix eval`
   в `python312Packages`; установка через pip не требуется.
4. Flake использует `genAttrs` вместо дополнительной зависимости flake-utils.
5. Канонический словарь связей (§4.5) имеет приоритет над примерами, где
   встречаются обратные `automated_by`, `has_participant` и отсутствующая `uses`.
   Обратные связи вычисляются, записывать их нельзя. Для чтения/записи данных
   используются `reads`/`writes`, для общей зависимости — `depends_on`.
6. Корень контекста возвращается целиком даже при бюджете меньше его размера
   (§7.5.1). Бюджет ограничивает соседей; ответ честно показывает фактическую
   длину. Сосед, не поместившийся ни одним разделом, входит в `omitted_ids`.
7. `raw` не имеет поля sensitivity в спецификации. Все исходники доступны
   с допуском `restricted`; метаданные и pending тоже. Это предотвращает
   чтение закрытого содержимого через исходник публичной страницы.
8. `app-doc` сохраняет полный slug после `appdoc-` (как определено §4.3),
   включая slug родительского приложения. `index` зарезервирован для app.
9. Короткий summary — ошибка схемы; `W_SUMMARY_WEAK` дополнительно доступен
   в мягком lint для файлов, изменённых вне сервиса. При submit ошибки
   ограничены изменёнными страницами и новыми проблемами наложения: чужой
   старый сломанный файл не должен блокировать независимое исправление.
10. Сроки хранятся как UTC ISO-8601 timestamps, а YAML-даты также принимаются.
    Точность времени нужна для `W_STALE_DEPENDENCY` при правках в один день.
11. Proposal виден только если клиент имеет доступ ко всем изменённым
    страницам, включая их предыдущие версии. Частичный diff может скрыть
    важную часть изменения, поэтому такое предложение возвращает 404.
12. Только автор или reviewer/admin может менять чужое предложение.
    Перед accept повторно проверяются версия main и всё наложение; конфликт
    слияния отменяется, main остаётся чистым, предложение сохраняется.
13. MCP SDK закреплён `>=1.29,<2`, соответствуя nixpkgs в flake.lock.
    Используем официальный FastMCP v1 и stdio; HTTP-транспорт необязателен.
    [Документация SDK v1](https://py.sdk.modelcontextprotocol.io/v1/).
14. nixpkgs `7a0f122` + Python 3.12: у `inline-snapshot 0.34.2` падают три
    snapshot-теста `tests/test_docs.py` (расходятся номера строк примеров).
    Flake исключает только этот файл тестов транзитивной build-зависимости;
    остальные тесты зависимостей и все проверки wikisvc остаются включены.
15. Полный reindex очищает производные таблицы и пересобирает их одной
    SQLite-транзакцией вместо удаления открытого WAL-файла. Читатели видят
    целостный снимок; статистика выдачи сохраняется. Индекс остаётся полностью
    удаляемым при остановленном сервисе. Без `--full` используются изменения Git.
16. Бюджет контекста считает `body_md`, без JSON и полей метаданных.
    Разделы H2/H3 неделимы при выдаче контекста; длинный абзац при поисковой
    индексации режется на части до 1500 символов, если границы абзацев не хватает.
17. Загрузка immutable raw — отдельный разрешённый коммит (§8.6), исключение
    из правила предложений для страниц. `note` хранится в state.db, не в raw.
18. Proposal наследует минимальный допуск автора при создании, а его diff
    дополнительно проверяет чувствительность всех старых и новых страниц.
    Аудит доступен только admin с restricted, поскольку содержит закрытые ID.
19. TTL проверяется при старте и создании нового предложения. Без фонового
    потока нет дополнительного процесса записи. Diff закрытого предложения
    хранится в state.db; после удаления worktree он остаётся доступен ревьюеру.
20. YAML-алиасы в frontmatter и схеме запрещены для защиты от рекурсивных
    структур. Значения задаются явно. Эта вики не требует YAML anchors.
21. Все редактирования сбрасывают страницу в draft, включая правки ревьюера.
    Подтверждение всегда выполняется явной операцией verify; verified_* клиент
    назначить не может. verify не меняет updated (дата фактического содержания).
22. Номер ADR — подсказка следующего свободного номера с учётом открытых
    предложений, а не бронирование. Конкурирующие создания проверяются на submit/accept.
23. Лимит запросов — фиксированная календарная минута в state.db, общий для
    HTTP и MCP одного токена. По умолчанию выключен. Запрос health не учитывается.
