# Выполнение спецификации

Этапы реализованы последовательно. Переход к следующему этапу выполнялся
после прохождения тестов предыдущего. Код — корень этого репозитория,
контент — отдельный соседний каталог `wiki/`.

| Этап | Реализация | Проверка на границе этапа |
|---|---|---|
| 0 | Python 3.12, flake/lock, CLI, конфигурация, justfile | 5 тестов; Ruff, mypy strict; nix flake check |
| 1 | Domain, 16 типов, YAML/Markdown, секреты, safe FS, init | 39 тестов, включая Hypothesis |
| 2 | Git/worktrees, flock, state.db, FTS5, индексация, граф | 43 теста; совпадение full/incremental, обратные связи и допуски |
| 3 | Токены, API чтения, поиск, контекст, схема | 46 тестов на корпусе из 35 страниц |
| 4 | Предложения, PATCH, diff, ревью, генераторы | 50 тестов; полный lifecycle, конфликт и атомарность |
| 5 | Сырьё, дедупликация, pending, извлечение текста | 52 теста; источник считается обработанным только после accept |
| 6 | Все W_*, lint, статистика, административный API | 54 теста |
| 7 | MCP stdio, 14 инструментов, та же авторизация | 55 тестов; настоящий MCP-клиент, включая отзыв токена |

В первоначальной реализации дополнительные граничные проверки довели набор до 70 тестов.
Покрытие `domain/` + `index/` в установленном Nix-пакете: **98,71%** при пороге 85%.
Ruff и `mypy --strict` проходят. Nix-сборка включает эти проверки и pytest с покрытием.

Финальная `nix flake check` на x86_64-linux прошла. Из собранного пакета
выполнены `init ../wiki`, `reindex --full` и `lint` (0 проблем). Проверен реальный
HTTP-запуск: health возвращает ok и текущий коммит, OpenAPI содержит 35 путей,
запрос страниц без токена возвращает 401. Проверочный процесс остановлен.
Оба репозитория находятся на main; рабочие токены автоматически не создавались.

Из необязательного этапа 8 включены аудит и лимит запросов на токен.
Провайдер эмбеддингов, векторное ранжирование и модуль NixOS не реализованы.
PDF/DOCX требуют необязательных библиотек; при их отсутствии сервис возвращает
ошибку с подсказкой. Основной сценарий извлечения текста проверен на TXT.

Известное предупреждение окружения: Starlette сообщает о будущем переходе
TestClient с httpx на httpx2. Проверки проходят с зависимостями из flake.lock.
Решения по неоднозначностям спецификации: [decisions.md](decisions.md).

## Исправления после внешнего ревью

Пункты 1–14 разобраны и исправлены:

- inbox/Obsidian не блокируют записи; служебные коммиты включают только нужные пути.
- Git-операции имеют журнал и откат, включая восстановление после завершения
  процесса; после сохранённого merge-коммита восстанавливается состояние proposal.
- Детектор секретов проверяет ключи в угловых скобках, URL-пароли и Bearer;
  обычные MD5/Git/SHA-256 допустимы вне контекста учётных данных.
- Понижение допуска видно в validate/diff; ни один редактор не может принять
  предложение, включая случаи последующих правок другим редактором.
- Авторизация предшествует чтению тела, анонимные отказы не растят audit,
  JSON ограничен 1 МиБ, PDF/DOCX извлекаются в ограниченном подпроцессе.
- Числовой score удалён из HTTP/MCP. Влияние скрытого корпуса на порядок
  BM25 не устранено полностью и явно описано в README.
- Индексация и proposals повторно разбирают только изменённые Markdown;
  локальная валидация кэшируется, связи проверяются на актуальном наборе страниц.
  Неизменённое raw повторно не читается для хеширования.
- Русские имена транслитерируются и сохраняются в оригинале; `1С`/`1C`
  нормализуются одинаково; слишком вложенный JSON возвращает клиентскую ошибку.

Также добавлены стартовые теги, запрет пустых proposals, `token list`, применение
`LOG_LEVEL`, группировка index.md по типам и автор/префикс в log.md. Инструкции
запуска описывают реальную структуру клонированного репозитория.

Воспроизводимый локальный замер: `nix develop -c python scripts/benchmark_proposals.py 1500`.
На 1500 синтетических страницах (три последовательных предложения): PUT
0,163–0,164 с, submit 0,114–0,120 с, accept 0,258–0,276 с.
Это измерение на текущей машине, а не сравнение одинаковых стендов с внешним ревью.

Итоговая проверка исправлений на x86_64-linux: **116 тестов**, покрытие ядра
**98,30%**, Ruff, `mypy --strict` и `nix flake check` прошли. Проверены реальные
PDF/DOCX, таймаут/память/размер вывода парсера, аварийное завершение процесса,
повторное принятие после сбоя, миграция старой state.db и внешний Git-коммит.

## Policy layer v2: этапы M1–M8

- M1: тип rule, типизированные ExtraField, scopes/profiles, новые связи,
  source.kind, защита полей, проверки правил и миграция через предложения.
  Проверки: 142 теста полного набора и отдельный тест миграции; Ruff и mypy strict.
- M2: компилятор, HTTP/MCP, экспорт и проверка блока CLI, добавление scopes,
  использование правил и бюджетный lint. 145 тестов, Ruff, mypy strict проходят;
  добавлены 40 правил и эталонный Markdown.
- M3–M8: в работе.

### M3 — граф и связанные правила (2026-10-02)

Готовы GraphStore/SqliteGraphStore, BFS с пакетными индексированными запросами,
impact, scopes в экспорте, ограниченные связанные тезисы, подбор правил и влияние
предложения. Поиск использует стоп-слова, синонимы, AND/OR fallback и lifecycle.
Удалены embeddings и их настройки. Проверки: 147 тестов, Ruff и mypy; отдельно
эталон старого графа и новые запросы. Бенчмарк 2000/10000/depth=3: медиана 7.86 мс.

### M4 — решения человека и находки (2026-10-02)

Токены person/kind/expires_at, whoami, CORS; типы предложений, заметки, фильтры,
атомарный accept с promote/deprecate и подтверждением активных правил; прямые
операции ревьюера; revert с обнаружением пересечений и восстановлением после
сбоя процесса. Находки проверяют цитаты, дедуплицируются по хешам и сохраняют
отклонение; принятие/откат связанного предложения меняют их состояние.
Rules list/stats/violations и inbox подключены. Статистика задач в inbox будет
подключена при добавлении wikiagent в M5. Проверки: 161 тест, Ruff, mypy strict.

### M5 — планировщик и чат wikiagent (2026-10-02)

Отдельный пакет/CLI, конфигурация ролей моделей, строгие ответы JSON, ограниченные
инструменты, agent.db и сессии, SSE, привязка к странице/правилу/предложению.
Конвейер извлечения/подбора/классификации/плана проверяет цитаты, строит черновики,
хранит версии переписки и обновляет то же предложение после ответа. Подтверждение
и откат возвращаются интерфейсу как человеческие действия. Общие объявления
инструментов используются MCP и моделью. Inbox может читать число задач из
WIKIAGENT_STATE_DIR/agent.db. Проверки: 167 тестов, Ruff и mypy strict.
12 YAML-сценариев на fake_llm: 100% совпадения, запретных вызовов нет.
Это проверка конвейера; реальная модель не оценивалась и production_ready=false
до достижения заданного спецификацией порога на 30 сценариях.
