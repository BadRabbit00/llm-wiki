# Знания по ходу работы
1. В начале задачи вызови get_brief(profile): это короткий список фактов, которые нужны всегда. Повторно за сессию не вызывай.
2. Перед проектным решением вызови ask(query, budget, scopes) по ключевым понятиям задачи. Формулируй запрос понятиями, а не вопросом целиком.
3. Если по области остались неясности, вызови list_questions: открытый вопрос может уже стоять на хабе.
4. Нужны детали факта - get_fact(id); соседние факты - expand(ids). Текст факта не пересказывай.
5. Ссылайся на знание только по ID (`f-…`, `top-…`, `tech-…`): в коде, комментариях и ответах пиши `[[f-…]]`, а не свои слова.
6. Факты со статусом outdated и confidence: contested используй с оговоркой и называй пару, а не выбирай сторону молча.
7. Нужного факта нет - не выдумывай. Предложи факт через propose_fact с confidence: inferred или заведи вопрос (question). Сценарий - fact-authoring.
8. Правила приходят в начале задачи (get_policies), знания запрашиваются по необходимости; не смешивай их.
