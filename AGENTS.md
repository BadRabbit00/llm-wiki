# Правила работы для агента в этом репозитории

Этот файл сильнее любых общих привычек. Нарушение — повод остановиться, а не «поправить потом».

## Контекст

Работающая, проверенная система: 10 629 строк `src/`, 4 039 строк тестов, порог покрытия ядра 85%,
`mypy --strict`, `ruff`, `nix flake check` гоняет всё целиком. Код написан намеренно так, как написан.

## Главное правило

**Не переписывай то, что работает.** Задача описывает добавление или точечное изменение.
Всё, что не названо в задаче прямым текстом, не трогается: ни рефакторинг «по пути», ни переименования,
ни смена стиля, ни «я сделал почище».

Что система делает и зачем — `SPEC.md`. Что сломано и в каком порядке правится — `fix.md`.
Задача берётся оттуда или от человека напрямую.

## Запрещено без явного пункта в задаче

- менять `src/wikisvc/services/proposals.py` (машина состояний, accept, revert, `E_SELF_REVIEW`);
- менять `src/wikisvc/storage/lock.py`, `src/wikisvc/services/auth.py`, `src/wikisvc/main.py:BodyLimit`;
- менять формат и семантику `src/wikisvc/tool_contracts.py` — это единый источник контрактов для HTTP, MCP и модели;
- менять формат `docs/` из шаблона документации (ID, мета-строки, статусы) — это источник правды, не наш внутренний формат;
- удалять или ослаблять тесты, понижать покрытие, добавлять `# type: ignore` без комментария с причиной;
- добавлять зависимости. Нужна новая — найди в nixpkgs (`nix search nixpkgs <имя>`), обоснуй в PR, обнови `flake.nix`;
- трогать `flake.lock` без необходимости, названной в задаче.

## Технические стандарты

- Python 3.12, строгая типизация. `Any` запрещён, кроме уже существующих мест в сигнатурах API.
- `try: ... except Exception: pass` запрещено. Ошибка либо обрабатывается, либо пробрасывается с контекстом.
- Блокирующий вызов в async-функции запрещён. Синхронная работа — через `run_in_threadpool`.
- Ошибки наружу — только `WikiError` с кодом `E_*`. Новый код ошибки документируется в задаче.
- Авторизация предшествует чтению тела запроса (см. `main.py:BodyLimit.__call__`). Этот порядок не меняется.
- Логи не содержат токенов, тел запросов и ответов модели (см. `src/wikiagent/cli.py:check_deployment`).

## Nix-first

- Любая команда — через окружение: `nix develop -c <команда>` или `nix shell nixpkgs#<пакет> -c <команда>`.
- `pip install`, `npm -g`, `cargo install` в систему — запрещены.
- Инлайн-исполнение (`python -c "..."`, `node -e "..."`) запрещено. Нужен скрипт — создай файл и запусти его.

## Перед тем как сказать «готово»

```sh
nix develop -c just lint          # ruff check + ruff format --check + mypy src
nix develop -c pytest --cov --cov-report=term-missing
nix flake check
```

Все три обязательны. Падает что-то — задача не сделана. Вывод тестов приводится в отчёте как есть.

## Процесс

- Одна задача = одна ветка = один коммит или PR. Не смешивай задачи в одном коммите.
- Задача противоречит коду или другой задаче — **остановись и спроси**. Не выбирай за человека.
- Чего-то не хватает в спеке — спроси. Не достраивай по догадке.
- Документация и код — в одном коммите.
- Коммиты атомарные, сообщение описывает «почему», а не «что».

## Границы системы, которые нельзя нарушить

Это инварианты продукта, а не стиль:

1. **Решения принимает человек.** `require_human()` (`services/auth.py:26`) требует `kind == "human"`.
   Ни один агент, ни один автоматический путь не получает `accept`, `promote`, `deprecate`, `revert`, `dismiss`.
2. **Автор не принимает своё предложение.** `E_SELF_REVIEW` сравнивает `actor.identity`. Не ослаблять.
3. **Новое правило от агента всегда инертное:** `lifecycle: candidate`, `level: should`, `priority: 3`.
4. **Ядро детерминировано.** `wikisvc` не вызывает LLM и не делает исходящих сетевых запросов. Не добавлять.
5. **Одноузловость.** Блокировка записи — `fcntl.flock` по локальному файлу. Не проектировать под несколько машин.
6. **Внешние данные недоверенные.** Ответы модели, книги, загруженные файлы и проектные документы
   проверяются, помечаются `untrusted_external` и никогда не исполняются.
7. **Потолок анонимного доступа задаётся кодом.** Анонимный принципал — всегда `kind="agent"`,
   роль не выше `writer`, допуск не выше `internal`. Конфигурация может только понизить, не повысить.
   Валидация падает при старте. Следствие: `restricted` закрыт, решения недоступны (см. п. 1).
8. **`wikiagent` не принимает анонимные вызовы.** Сравнение допуска вызывающего с допуском
   рабочего токена агента (`src/wikiagent/api.py:86-91`) не ослабляется ни для какого удобства:
   через агента нельзя получить то, чего не видно напрямую.

- [SHOULD] Просят объяснить или сделать ревью — отвечай текстом без правок; просят план — короткий список, а не многостраничный документ. → rule-ai-answer-format
- [SHOULD] Давай каждую цифру и факт вне кода проекта со ссылкой на первоисточник; нет источника — нет цифры, прогнозы помечай. → rule-ai-cite-sources
- [SHOULD] Для документа, презентации или крупной фичи сначала согласуй тезисный план, а материал собирай после одобрения. → rule-ai-plan-big-materials
- [SHOULD] Предупреждай перед созданием тестовых данных в общем окружении и удаляй всё созданное, но никогда чужое. → rule-ai-test-data-cleanup
- [SHOULD] Дорабатывай выбранный пользователем вариант на месте; новые варианты — только по просьбе и не больше двух. → rule-ai-variants-on-request
- [SHOULD] Предлагай одно решение; варианты — только по просьбе, не больше двух, отличаются идеей и показаны макетом в браузере. → rule-design-variants
- [SHOULD] Описывай статусы, роли, тарифы и лимиты enum'ом, константой или конфигом, а не строками и числами в коде. → rule-arch-no-magic-values
- [SHOULD] Используй контейнер до 1440px с 12 колонками, поля через `clamp()` и асимметричную шапку секции. → rule-design-grid-spacing
- [SHOULD] Используй линейные иконки на сетке 24px с линией 1.5px inline SVG с `currentColor`; эмодзи вместо иконок запрещены. → rule-design-icons
- [SHOULD] Делай фиксированную шапку с 4–6 пунктами, `aria-current` и маленькой кнопкой действия; мобильное меню закрывается по Esc и держит фокус. → rule-design-navigation
- [SHOULD] Держи строку текста 45–75 знаков, выключку влево, капс — только для мелких меток, цифры — `tabular-nums`, размеры — через `clamp()`. → rule-design-type-scale
- [SHOULD] Фичи не импортируют друг друга, `shared/ui` не знает домена, env читается только в `shared/config/env.ts`, тексты — ключами i18n. → rule-arch-frontend-structure
- [SHOULD] Пиши структурированные логи в stdout с request-id, разделяй `/health` и `/ready`; при трёх и более сервисах — OpenTelemetry и Prometheus. → rule-stack-observability
- [SHOULD] Используй `Authorization: Bearer` для мобильных приложений, CLI и интеграций через отдельный вход; токены мобильных — в Keychain/Keystore. → rule-auth-bearer-clients
- [SHOULD] Используй coverage, чтобы найти непроверенные ветки; тесты ради процента без проверок запрещены, порог покрытия не понижается. → rule-test-coverage-not-goal
- [SHOULD] Держи тесты в папке компонента, а не в корневом `tests/`; имя теста — утверждение о поведении. → rule-test-location-naming
- [SHOULD] Пиши тест как «подготовка → действие → проверка» с одним правилом, конкретными ожиданиями и минимальными данными. → rule-test-structure
- [SHOULD] Предлагай TDD, но не навязывай; отказался пользователь — тесты пишутся после реализации в той же задаче. → rule-test-tdd-offer
- [SHOULD] Тестируй фронтенд через Vitest и Testing Library с MSW, e2e — Playwright; без Enzyme и снапшотов страниц как единственной проверки. → rule-test-tools-frontend
- [SHOULD] Пиши тесты на Python через pytest, pytest-asyncio, httpx `AsyncClient`, фабрики и respx; unittest как раннер не используется. → rule-test-tools-python
- [SHOULD] Браузеры Playwright, драйверы и прекомпилированные бинари бери из nixpkgs; `nix-ld` и другие обходы — только с согласия. → rule-nix-binaries-from-nixpkgs
- [SHOULD] Поднимай PostgreSQL, Redis и брокер для разработки контейнером из compose или временным экземпляром из devShell, как принято в проекте. → rule-nix-dev-infrastructure
- [SHOULD] Включай несвободные пакеты (`allowUnfree`, `NIXPKGS_ALLOW_UNFREE`) только с согласия пользователя. → rule-nix-unfree-consent
- [SHOULD] Вызывай LLM через официальные SDK за своим интерфейсом провайдера; локальные модели — отдельным контейнером. → rule-stack-llm-providers
- [SHOULD] Бери Caddy по умолчанию на VPS, nginx — для SPA в контейнере и тонкой настройки, Cloudflare Tunnel — для показа стенда. → rule-stack-reverse-proxy
- [SHOULD] Не публикуй auth наружу, ходи к нему через обратный прокси; `keygen` идемпотентен, а удаление тома ключей — только с подтверждения. → rule-auth-compose-runtime
- [SHOULD] Пиши на языке пользователя просто и по делу, называй реальные файлы и команды, не возвращайся к закрытым темам. → rule-ai-communication
- [SHOULD] Задавай вопросы интерактивным инструментом с вариантами или нумерованным списком с ответом цифрой и рекомендуемым вариантом первым. → rule-ai-question-format
- [SHOULD] Для задачи, меняющей файлы, веди `todo.md`: шаг — проверяемое действие с путями, отмечай по ходу, последние шаги — проверки и отчёт. → rule-ai-todo-file
