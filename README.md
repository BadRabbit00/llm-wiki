# wikisvc

Сервис для markdown-вики в отдельном git-репозитории: Python 3.12, FastAPI,
SQLite FTS5, типизированный граф, предложения через git worktree и MCP stdio.
Сервис не вызывает LLM. Реализованы этапы 0–7 спецификации, а также аудит
через API и необязательный лимит запросов на токен.

```text
work/
├── backend/              # код, flake, тесты
│   └── .dev/
│       ├── state/        # токены, предложения, аудит, worktrees; нужен бэкап
│       └── index/        # пересобираемый индекс
└── wiki/                 # независимый git-репозиторий контента
    ├── AGENTS.md
    ├── CLAUDE.md -> AGENTS.md
    ├── inbox/
    ├── raw/
    ├── wiki/
    └── schema/
```

## Запуск

```sh
cd backend
nix develop

# Только для нового пустого каталога контента:
wikisvc init ../wiki

wikisvc token create --name agent --role writer --clearance restricted
wikisvc token create --name human --role reviewer --clearance restricted
wikisvc serve
```

Каждый токен показывается один раз; в базе хранится только SHA-256. Сохраните
выданные значения в своём хранилище секретов. Автор предложения не может
принять его, поэтому агенту и человеку нужны разные имена токенов.
Токены для вашей рабочей вики автоматически не создаются.

Dev shell задаёт `WIKI_ROOT=../wiki`, `STATE_DIR=$PWD/.dev/state`,
`INDEX_DIR=$PWD/.dev/index`. Переменные можно переопределить до `nix develop`.
Команды dev shell запускайте из `backend/`.

API: `http://127.0.0.1:8787/api/v1`; OpenAPI: `/openapi.json`, документация: `/docs`.
Сервис использует один процесс. Переменные `BIND_HOST` и `BIND_PORT` меняют адрес;
при внешнем доступе нужен обратный прокси с TLS.

```sh
curl http://127.0.0.1:8787/api/v1/health
curl -H "Authorization: Bearer $WIKI_TOKEN" \
  'http://127.0.0.1:8787/api/v1/search?q=выгрузки%20счетов&expand=true'

wikisvc reindex --full
wikisvc lint
wikisvc token revoke agent
```

`wikisvc lint` завершает работу с кодом 1 при ошибках `E_*`, предупреждения
`W_*` не меняют код возврата. `reindex --full` пересобирает весь индекс,
`reindex` обновляет файлы, изменённые с последней индексированной версии Git.
После изменения схемы администратором выполните `reindex --full`.

## Работа с предложениями

1. `GET /schema/instructions`, затем поиск и чтение контекста.
2. `POST /proposals` с `title` и `description`.
3. `PUT /proposals/{pid}/pages/{id}` с `frontmatter`, `body_md` и
   `base_version` текущей страницы из main, если она уже существует.
4. `PATCH` поддерживает операции над полями, тегами, источниками, связями,
   разделами и точными строками. Весь набор операций атомарен.
5. `GET /proposals/{pid}/validate`, исправление ошибок, `POST .../submit`.
6. Другой токен с ролью reviewer: `GET .../diff`, затем
   `POST .../accept`, `POST .../reject` или `POST .../request-changes`.

PUT также принимает `Content-Type: text/markdown`; версию передавайте в
заголовке `If-Match`. Даты, сведения о проверке и статус при редактировании
назначает сервис. Для подтверждения страницы есть `POST /pages/{id}/verify`,
для устаревания — `POST /pages/{id}/mark-outdated` с `reason`.

При конфликте слияние отменяется, main остаётся чистым, предложение получает
статус `conflict` и сохраняется. Можно отказаться от него через `abandon`
и подготовить новое на актуальном main. Закрытые предложения сохраняют diff
в state.db, даже после удаления их worktree. Неактивные предложения закрываются
по `PROPOSAL_TTL_DAYS` при старте и создании новых предложений.

В существующей вики старые ошибки в неизменённых страницах не блокируют
независимое предложение; новые ошибки наложения и ошибки изменённых страниц
блокируют submit. После Git-слияния результат проверяется ещё раз до коммита.

## Поиск, контекст и доступ

Поиск нормализует русские и английские словоформы и использует BM25. Поддержаны
AND по умолчанию, фразы в кавычках, префиксы `слово*`, фильтры и расширение
по графу. Источники, wikilinks и канонические связи дают рёбра; обратные связи
вычисляются. Граф ограничен глубиной 5.

`GET /context/{id}` возвращает корень целиком, затем соседей в пределах бюджета.
`delivered_chars` и `available_chars` считают символы `body_md`; JSON и метаданные
не входят в бюджет. Корень может превысить бюджет, как требует спецификация.
Невместившиеся соседи отмечаются в `truncated_ids`, полностью опущенные — также
в `omitted_ids`. Статистика доступна через `/stats`.

Роли: reader → writer → reviewer → admin. Допуск независим от роли:
public → internal → restricted. Закрытые страницы дают 404 и скрываются
из поиска, графа, контекста, индекса, истории и diff. Предложение показывается
только целиком и только при достаточном допуске, включая предыдущие версии.

## Сырьё

`POST /raw` принимает multipart `file`, `category` и необязательный `note`.
Допустимые категории: docs, transcripts, tickets, api-specs, code-samples, assets.
Есть лимит размера, проверка расширения и сигнатуры, очистка имени и дедупликация
по SHA-256. Сырьё нельзя перезаписать или удалить через API. Загрузка добавляет
исходник отдельным коммитом; страницы знаний по-прежнему меняются предложениями.

В спецификации у сырья нет sensitivity, поэтому всё сырьё, его метаданные и
pending доступны только с `clearance=restricted`. Для ingest используйте токен
с этим допуском. Текст возвращается с `trust: untrusted_external`, оригинал —
как attachment с `X-Content-Trust: untrusted_external` и `nosniff`.

`GET /sources/pending` вычисляет необработанные файлы по отсутствию принятой
source-страницы с соответствующим `raw_sha256`. Сервис сверяет hash и raw_path
при создании source. Текстовые форматы читаются напрямую; для PDF/DOCX нужны
необязательные `pypdf`/`python-docx` из группы зависимостей `documents`.
XLSX и изображения доступны для скачивания, без извлечения текста.

## MCP

В той же оболочке задайте `WIKI_TOKEN` ранее выданным токеном и запустите:

```sh
wikisvc mcp
```

В клиенте MCP используйте stdio-команду установленного `wikisvc` с аргументом
`mcp`, передав `WIKI_ROOT`, `STATE_DIR`, `INDEX_DIR` и `WIKI_TOKEN` через окружение.
Пакет можно собрать `nix build`, команда появится в `result/bin/wikisvc`.

Доступны 14 инструментов: get_instructions, search, get_page, get_context,
neighbors, list_pending_sources, read_source_text, get_page_template,
create_proposal, put_page, patch_page, validate_proposal, submit_proposal, lint.
Инструментов принятия и отклонения нет. Токен проверяется при каждом вызове,
включая проверку отзыва и необязательный лимит частоты.

## Проверки и эксплуатация

```sh
just test
just lint
pytest --cov=wikisvc.domain --cov=wikisvc.index --cov-report=term-missing
nix flake check
```

Тесты используют настоящие временные git-репозитории, FastAPI TestClient,
Hypothesis и настоящий MCP-клиент через stdio. Корпус содержит 35 страниц.
Порог покрытия ядра — 85%. Nix фиксирует зависимости через `flake.lock`;
точечный workaround для upstream-тестов описан в decisions.md.

`POST /admin/reindex` требует admin. `GET /admin/audit` дополнительно требует
restricted и поддерживает фильтры `since`, `token`, `action`. Выдача и отзыв
токенов доступны только в CLI. `RATE_LIMIT_PER_MIN=0` выключает лимит;
положительное число задаёт лимит вызовов на токен в календарную минуту.

Резервируйте контент и весь `STATE_DIR` согласованно, остановив запись на время
копирования. `INDEX_DIR` можно удалить при остановленном сервисе и пересобрать.
`inbox/` не индексируется. История Git остаётся источником правды, внешний ручной
коммит требует переиндексации. Перед записью main должен быть чистым.

Векторный провайдер и NixOS-модуль отложены как необязательная часть этапа 8.
`hybrid` без провайдера использует BM25; `vector` возвращает понятную ошибку.
Интерфейс расширения — `EmbeddingProvider`. Никаких вызовов моделей внутри
текущей реализации нет.
