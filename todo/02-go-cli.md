# 02 — Go CLI `wk`

## Цель

Один статический бинарь, который заводит проект, держит связь проекта с викой и даёт
единый гейт проверок. Раздаётся как файл, живёт в `devShell` каждого проекта.

## Размещение и сборка

- каталог `cli/` в этом репозитории (рядом с `ui/`);
- `cli/package.nix` по образцу `ui/package.nix`: `pkgs.buildGoModule`, `env.CGO_ENABLED = "0"`, `vendorHash`;
- `flake.nix`: `packages.wk`, `apps.wk`, добавить в `checks` прогон `go test ./...` и `go vet ./...`;
- Go 1.24+, только стандартная библиотека и `gopkg.in/yaml.v3`. Других зависимостей нет;
- имя бинаря `wk` задаётся в одном месте (`postInstall`), чтобы менялось одной правкой.

## Манифест

Файл `.wiki-project.yaml` в корне проекта. Единственный источник параметров для всех команд.

```yaml
version: 1
project: orders-platform          # [a-z0-9][a-z0-9-]{0,63}
wiki:
  url: https://wiki.company.internal   # без пути, только origin
  profile: go-service                  # должен существовать в вике
  scopes: [lang:go, app:orders]        # все должны существовать в вике
policy_blocks:
  - file: AGENTS.md
    profile: go-service
template:
  id: go-service
  digest: sha256:3f91c2e...         # пусто, если проект создан без шаблона
docs:
  root: docs
```

Требования:

- токена в манифесте нет и быть не может. Валидация отвергает любой ключ, содержащий `token`/`secret`/`password`;
- неизвестные ключи верхнего уровня — ошибка, не предупреждение;
- `wiki.url` — только `http`/`https`, без пути, без query, без учётных данных в URL;
- `policy_blocks[].file` — относительный путь внутри проекта, без `..`, без абсолютных путей, без симлинков;
- `version: 1` обязателен; иное значение — ошибка «обнови `wk`».

## Доступ к вике

`wk` работает **без credential**. Запросы уходят без заголовка `Authorization`, wikisvc отвечает
анонимным принципалом (`writer` / `agent` / `internal`, задача 09). Граница доступа — сеть:
loopback, SSH-туннель или закрытый сегмент.

- переменная `WIKI_TOKEN` поддерживается как необязательная: задана — подставляется в `Authorization`,
  не задана — запрос идёт анонимно. Нужна только человеку, запускающему `wk` с сессионным токеном;
- токен никогда не пишется на диск, не попадает в логи и в вывод, не передаётся аргументом;
- команды решений (`accept`, `promote`, `revert`) в `wk` отсутствуют, поэтому прав анонима достаточно
  для всего, что эта тулза делает;
- `wk` не предлагает `wk login` и не участвует в OIDC-потоке. Вход людей — только через UI.

## Команды

Все выводят человекочитаемый текст; с `--json` — машинный JSON на stdout, диагностику на stderr.

### `wk init [--profile <id>] [--template <id>] [--existing] [--dir .]`

1. отказ, если каталог не пуст и нет `--existing`;
2. `git init`, если репозитория нет; существующий не трогается;
3. раскладка `docs/` из шаблона (см. ниже). При `--existing` — только `docs/`, `AGENTS.md`, манифест;
4. `AGENTS.md`: блок docs-kit (`AGENTS-snippet.md`) + блок политик (см. задачу 07);
5. манифест с заполненными `project`, `wiki`, `policy_blocks`, `template`;
6. `.gitignore`: `result`, `result-*`, `.direnv`, `.env`;
7. `flake.nix` с `devShell`, в котором доступен `wk`;
8. ничего не коммитит. Коммит — решение человека.

Идемпотентность: повторный `init` на готовом проекте без `--force` ничего не меняет и выходит с кодом 0.

### `wk doctor [--json]`

Проверки по порядку, каждая — отдельная строка результата `ok` / `warn` / `fail`:

| проверка | как |
|---|---|
| манифест валиден | разбор и валидация схемы |
| вика доступна | `GET {url}/api/v1/health` → `status == "ok"` |
| кто мы для вики | `GET /api/v1/whoami` → печатает `name`, `role`, `kind`, `clearance`. 401 → `fail` с текстом «анонимный доступ выключен на сервере»; `role=reader` → `warn`: предложения создавать нельзя |
| профиль существует | `GET /api/v1/profiles` содержит `wiki.profile` |
| scopes существуют | `GET /api/v1/scopes` содержит все `wiki.scopes`; отсутствующие перечислить |
| блок политик свежий | сверка хеша версии (задача 07) |
| MCP доступен | `POST {url}/mcp` `tools/list`; при 404 — `warn`, не `fail` |
| агент доступен | `GET {url}/agent-api/healthz`; недоступен — `warn` |
| документация проходит | встроенная проверка (задача 06) |
| git без незакоммиченного | `git status --porcelain` пуст; иначе `warn` |

Код выхода: 0 — всё `ok`/`warn`; 1 — есть `fail`.

### `wk component add <name> [--lang <LANG-id>] [--kind svc|lib]`

1. `docs/components/<name>/` из `docs/components/_template/`;
2. в каждом файле заменить плейсхолдеры: ID (`SVC-<name>` или `LIB-<name>`), `status: draft`,
   `owner: SVC-<name>` там, где `owner` обязателен;
3. `ai.md` создаётся только с `--with-ai`;
4. добавить строку в таблицу «Компоненты» в `docs/INDEX.md`; таблица уже содержит компонент — ошибка;
5. имя: `[a-z0-9][a-z0-9-]{0,31}`.

### `wk check [--strict] [--json]`

Единый гейт: встроенная проверка документации (задача 06) **и** проверка свежести блока политик (задача 07).
Код выхода 1, если есть ошибки или (`--strict`) предупреждения. Эта команда вешается в хук агента и в CI.

### `wk policy sync` / `wk policy check`

См. задачу 07.

### `wk propose --file <path> [--title <s>] [--kind manual]`

1. `POST /api/v1/proposals` → `pid`;
2. `PUT /api/v1/proposals/{pid}/pages/{page_id}` телом из файла;
3. `GET /api/v1/proposals/{pid}/validate`; ошибки — печатает и **не** отправляет;
4. `POST /api/v1/proposals/{pid}/submit`;
5. печатает `pid` и ссылку на UI.

Команда не умеет `accept`, `promote`, `deprecate`, `revert` и не получает таких флагов. Никогда.

### `wk policy search <q>` / `wk policy show <rule-id>`

`GET /api/v1/rules/related?q=` и `GET /api/v1/rules/{id}`, компактный вывод в терминал.

### `wk template list` / `wk template show <id>`

Список и содержимое шаблонов (см. ниже).

## Шаблоны проектов

**Источник правды — вика.** Шаблоны лежат в `schema/project-templates/<id>.yaml` git-репозитория вики,
правятся администратором, предложениями не меняются. Доставка: `GET /api/v1/schema` уже отдаёт реестр —
добавить шаблоны в загрузчик реестра (`src/wikisvc/storage/schema.py`) и эндпоинт
`GET /api/v1/schema/project-templates/{id}`. Это **часть этой задачи**, серверная половина.

Формат шаблона:

```yaml
id: go-service
title: Go HTTP-сервис
profile: go-service
scopes: [lang:go, app:service]
components:
  - { name: api, kind: svc, lang: LANG-go }
files:
  - { path: flake.nix, content: | ... }
  - { path: .gitignore, content: | ... }
policy_blocks:
  - { file: AGENTS.md, profile: go-service }
```

### Безопасность шаблонов — обязательные правила

Шаблон — это удалённый генератор кода. Нарушение любого пункта делает его каналом исполнения кода.

- **хуков нет.** Поля вида `post_init`, `exec`, `script`, `command` не поддерживаются. Встретилось — ошибка разбора;
- путь каждого файла проверяется **до записи**: относительный, без `..`, без ведущего `/`,
  не указывает в `.git/`, целевой путь после разрешения остаётся внутри каталога проекта;
- симлинки не создаются и не перезаписываются;
- лимиты: не больше 200 файлов, суммарно не больше 2 МиБ, один файл не больше 256 КиБ;
- существующий файл не перезаписывается без `--force`; список конфликтов печатается;
- после применения `template.digest` в манифесте = `sha256` канонического YAML шаблона;
- `--offline` работает из локального кэша (`$XDG_CACHE_HOME/wk/templates/<id>-<digest>.yaml`);
- источник `github:` допускается только явным флагом `--template github:owner/repo#id` и только для `init`.

## Тесты

`cli/..._test.go`, только стандартный `testing`:

1. валидация манифеста: неизвестный ключ, `..` в пути, ключ с `token`, кривой URL — каждая даёт ошибку;
2. `init` в пустом каталоге: состав файлов, идемпотентность повторного запуска;
3. `init` в непустом без `--existing` — отказ;
4. `component add`: файлы, подстановки, строка в `INDEX.md`, повтор — ошибка;
5. `doctor` против `httptest.Server`, отдающего заготовленные ответы: все ветки `ok`/`warn`/`fail` и коды выхода;
6. шаблон с `path: ../evil`, с абсолютным путём, с `post_init`, с 300 файлами, с файлом 1 МиБ — все отвергнуты;
7. `digest` стабилен при перестановке ключей во входном YAML;
8. токен не появляется ни в stdout, ни в stderr ни в одной команде (проверять подстрокой).

## Готово, когда

- `nix build .#wk` даёт бинарь; `nix run .#wk -- doctor` работает в проекте с манифестом;
- `go vet ./...` и `go test ./...` зелёные, включены в `nix flake check`;
- `cli/README.md`: таблица команд, схема манифеста, формат шаблона, правила безопасности шаблонов.

## Не делать

- не реализовывать компиляцию политик на клиенте — версия-хеш считается сервером;
- не кэшировать токен, не писать его в файл, не предлагать `wk login` в этой задаче;
- не давать команд принятия/повышения/отката;
- не тащить cobra, viper, logrus и прочее: стандартная библиотека + `yaml.v3`;
- не делать `wk` обёрткой над `git` вообще — только `init` и `status --porcelain`.
