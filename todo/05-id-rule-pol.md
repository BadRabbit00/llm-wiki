# 05 — Развод ID: инвариант домена против политики компании

## Проблема

Два разных факта называются одним словом:

- docs-kit `RULE-order-min-total` — бизнес-инвариант проекта, определяется в `docs/system/domain.md`;
- вика `rule-async-only` — политика написания кода, страница `rules/<slug>.md` в репозитории вики.

Механической коллизии нет: `REF_RE` в `check.py` регистрозависим, прописные префиксы не матчат
строчное `rule-`. Коллизия **семантическая**: человек и модель видят в одном документе `RULE-…` и `rule-…`
и обязаны угадывать, какая из двух систем имеется в виду.

## Решение

### 1. В docs-kit переименовать `RULE` → `INV`

Сейчас это 19 вхождений в шаблоне и примере, в реальных проектах — ноль. Через полгода это будет невозможно.

Правки в `/home/BadRabbit/work/docs-kit`:

| файл | что |
|---|---|
| `docs/_meta/ids.md` | в таблице «Система и домен»: `INV` — «бизнес-правило / инвариант», файл `system/domain.md` |
| `docs/_meta/check.py` | `LOCATION`: ключ `RULE` → `INV`; `GROUPS`: в группе «Система и домен» `RULE` → `INV` |
| `docs/system/domain.md` | заголовок `### RULE-<имя>` → `### INV-<имя>`, строка `- rules:` → `- invariants:` |
| `docs/components/_template/{code,contracts,data}.md` | `RULE-<…>` → `INV-<…>` |
| `example/docs/**` | все `RULE-order-*` → `INV-order-*`, включая `errors.md`, `flows.md`, `runtime.md`, `code.md`, `data.md`, `contracts.md` |
| `docs/_meta/format.md` | если упоминается `RULE` — заменить |

После правок `python3 example/docs/_meta/check.py --strict` проходит без ошибок и предупреждений.

### 2. Политики вики ссылаются своим настоящим ID

В проектных документах политика упоминается ровно так, как она называется в вике: `rule-async-only`,
строчными. Никакого второго написания, никакого префикса-синонима, никакой таблицы соответствий.

Причина техническая, не вкусовая: версия блока политик считается как
`sha256([sorted((page.id, page.version)), parameters])[:8]` (`src/wikisvc/services/policies.py:175`),
а формат строки задаёт `_line()` (`policies.py:167-172`) и в хеш **не входит**. Значит изменение формата
вывода ID не поднимет версию, и устаревшие блоки перестанут определяться как устаревшие.
Поэтому `_line()` и экспортёр в этой задаче **не меняются**.

### 3. Проверяющий инструмент узнаёт про внешние ID

Задача 06 портирует проверку в `wk`. Там же:

- ID, перечисленные в блоке `<!-- wikisvc:begin … --> … <!-- wikisvc:end -->`, регистрируются как
  **внешние определения**: на них можно ссылаться из любой карточки, их нельзя определять в `docs/`;
- ссылка на `rule-…`, которого нет в блоке → ошибка: «политика не входит в профиль проекта,
  проверь `wk policy sync` или профиль в манифесте»;
- попытка определить `rule-…` внутри `docs/` (заголовком или строкой таблицы) → ошибка:
  «политики определяются в вике, здесь только ссылки»;
- в `registry.md` внешние ID идут отдельной секцией «Политики компании» с колонками
  `id | уровень | профиль`, без колонок «определён» и «используют» для места определения.

### 4. Документация

- `docs/_meta/ids.md`: раздел «Внешние ID» — `rule-…` приходят из вики через блок политик,
  определяются там, здесь только ссылки, менять блок руками нельзя;
- `AGENTS-snippet.md`: строка «Инвариант домена — `INV-…`, политика компании — `rule-…`. Это разные вещи».

## Готово, когда

- `grep -rn "RULE-" /home/BadRabbit/work/docs-kit` пуст;
- `python3 example/docs/_meta/check.py --strict` проходит;
- `src/wikisvc/services/policies.py` не изменён;
- `ids.md` содержит `INV` и раздел «Внешние ID».

## Не делать

- не менять `_line()`, шаблон политики и формат блока — это сломает определение устаревших блоков;
- не менять ID правил в вике: `ids.md` вики запрещает переименование, и это правильно;
- не вводить `POL-` как второе имя для `rule-` — два написания одного факта хуже одного неудобного.
