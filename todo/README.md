## Порядок выполнения

```
08 ──────────────────────────────── можно сразу, независимо
01 ──────────────────────────────── можно сразу, независимо
05 ──┐
02 ──┴─→ 06 ──┐
     └─→ 07A ─┴─→ 03, 04
              └─→ 07B
```

- **08** и **01** ни от чего не зависят, делаются параллельно с остальным.
- **02** и **05** — основание. Без них 06, 07A, 03 и 04 делать нечего.
- **04** больше ничем не заблокирована: 02, 06 и 07A сделаны, `wk check --strict` работает.
  Гейт на остановке вызывает обёртку `wk hook check`, а не `wk check --strict` напрямую:
  блокирует только код 2, а прямая команда даёт 1 при ошибках и 3 без сети. См. 04, пункт 1.
- **07B** (сверка документации моделью) — самая крупная задача, браться после 07A.
  Запускается из UI: `wikiagent` не принимает анонимные вызовы, `wk audit` в первой версии нет.

## Вне очереди

- **Упаковка в distroless-образ** через `pkgs.dockerTools.buildLayeredImage`.
- **Реестр проектов на сервере** — какой репозиторий на какой версии политик.
- **Многофайловый экспорт** политик в структуру docs-kit. Пока всё в `AGENTS.md`, этого достаточно.

## Решено не делать

- Не портировать ядро на Go или Rust: 10 629 строк `src/` + 4 039 строк тестов, извлечение PDF
  ухудшится, git всё равно вызывается подпроцессом. Go — на краю, Python — в ядре.
- Не форкать кодящего агента. Интеграция — это определения инструментов, остальное в агенте чужое.
- Не проектировать под несколько узлов: блокировка записи — `fcntl.flock` по локальному файлу.
